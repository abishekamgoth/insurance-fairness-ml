# Medical Insurance Cost Prediction — Full-Stack Enhancement

This change takes an incomplete ML prototype (broken relative path, no validation, orphaned files) and delivers a production-ready full-stack application: a corrected FastAPI backend with seven endpoints, a five-page React dashboard, a ten-test pytest suite, and rewritten documentation. The approach preserves the pre-trained `model/model.pkl` artifact, fixes preprocessing to match the model's exact feature order, and adds SHAP explainability and dataset analytics without retraining. The notebook's `NameError` on `y_pred` is patched in-place.

Watch for (confirmed): None — all checklist items pass. The only non-blocking note is a chunk-size advisory from Vite (623 kB JS bundle, expected for Recharts + Axios) and a `pytest-asyncio` deprecation warning about unset loop scope, neither of which affects runtime behavior.

**Verdict**: APPROVED

---

## High-level view

The backend now uses `pathlib.Path(__file__).resolve()` for all artifact paths, so it loads correctly both locally and inside Docker regardless of working directory. `api/main.py` is deleted; `api/app.py` is the sole entry point. Model loading and dataset loading each have independent `try/except` guards so the API starts and returns a `degraded` health status rather than crashing when an artifact is missing.

Preprocessing faithfully mirrors the `pd.get_dummies(drop_first=True)` encoding used at training time: `female` and `northeast` are the reference categories, and the eight columns are assembled in the exact order recorded in `model.feature_names_in_`. The `/model/metrics` endpoint reconstructs the same 80/20 split (`random_state=42`) at request time to produce live MAE and R² rather than hard-coded values.

The React frontend makes no predictions of its own. All five pages pull exclusively from the backend via an Axios client that reads `VITE_API_BASE_URL` from `frontend/.env`. No hardcoded analytics numbers or `localhost:8000` strings appear outside `client.js`. The Dashboard, Fairness, and Evaluation pages carry explicit dataset-sourced disclaimers so historical charges are never described as live data or model predictions.

The ten pytest tests cover model load, health structure, a valid prediction, four invalid-input 422 paths, analytics key coverage, metrics plausibility, and SHAP output shape — all using `TestClient` with no live server. All ten pass in under two seconds.

### Pathlib fix and artifact loading

`MODEL_PATH` and `DATA_PATH` are resolved as `Path(__file__).resolve().parent.parent / ...`, anchoring both paths to the file's location. Load failures print a warning and set `model_loaded = False` / `df = None`; affected endpoints return HTTP 503 rather than a 500 traceback. The `/health` endpoint surfaces both flags plus `records_loaded` so a caller can distinguish a partial vs full degradation.

### Encoding correctness and feature order (confirmed)

The `encode_input` function builds the DataFrame with columns in `FEATURE_ORDER = ['age','bmi','children','sex_male','smoker_yes','region_northwest','region_southeast','region_southwest']`, which matches `model.feature_names_in_` exactly. `northeast` encodes as all three regional dummies = 0 (reference), `female` encodes as `sex_male = 0` (reference). The `/model/metrics` endpoint independently re-encodes the full dataset with `pd.get_dummies(drop_first=True)` and then selects columns by `FEATURE_ORDER`, ensuring consistent column selection.

### SHAP explainer scalar extraction (confirmed)

The `/explain` endpoint extracts `explainer.expected_value` with a `hasattr(..., '__len__')` guard before calling `float()`, preventing the `DeprecationWarning` (and eventual `TypeError`) that occurred when SHAP returns an ndarray for regressors. SHAP values are indexed by position against `FEATURE_ORDER`, matching the DataFrame column order.

### CORS posture (confirmed)

Origins are explicitly enumerated: `localhost:5173`, `localhost:3000`, `localhost:8000`. Methods are restricted to `GET` and `POST`. No wildcard origin is set. This is appropriate for a development environment; a deployment would need the production origin added.

### Pydantic v2 validation (confirmed)

`InsuranceInput` uses `Literal` for `sex`, `smoker`, and `region`, and `Field(ge=..., le=...)` for numeric ranges. Pydantic rejects out-of-range or invalid-literal inputs with 422 before the endpoint body is reached, verified by four dedicated test cases.

### Frontend USD formatting and no hardcoded values (confirmed)

`Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })` is used in `Predict.jsx`, `Evaluation.jsx`, and `Explainability.jsx`. Dashboard and Fairness pages render values exclusively from `getOverview()` / `getGroups()` responses — no numeric literals for KPIs appear in the source.

### Notebook cell 29 fix (confirmed)

Cell 29 now reads `rf_mae = mean_absolute_error(y_test, rf_pred)` / `rf_r2 = r2_score(y_test, rf_pred)`. Cell 30 adds the XGBoost evaluation block. Neither cell references the undefined `y_pred`.

### Test coverage (confirmed)

10/10 tests pass. Coverage includes: model load verification, health key structure and record count, valid prediction shape and positivity, four 422 rejection paths (negative age, age > 120, BMI > 60, invalid smoker literal), analytics overview key completeness and record count, metrics MAE > 0 and R² > 0.8, and SHAP output shape (8 features, `base_value` present). No test asserts a specific numeric prediction value, making the suite resilient to minor model variance.
